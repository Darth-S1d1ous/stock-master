# stock-master-bot (智能洞察驱动系统)

## 项目简介
stock-master-bot 是一个基于 **Agno 框架** 构建的智能化、事件驱动的分析系统。它旨在解决复杂环境下数据处理的时效性与洞察准确性问题，通过将 **大模型 (LLM) 的非结构化理解能力** 与 **确定性的后端工程逻辑** 有机结合，实现了从任务调度、实时事件触发到智能分析的完整闭环。

本项目聚焦于美股投资研究场景，不以“通用 AI 工作流引擎”为最终定位，而是构建一个 **可审计的投资论点监控与事件研究平台**。

## 产品定位与长期价值

### 核心问题

随着通用大模型和 Agent 能力提升，联网搜索、股票问答、财报总结、定时任务和普通报告生成会逐渐成为基础能力。项目的长期价值不能依赖“接入了某个模型”或“能够生成一份报告”，而应来自模型之外持续积累的领域资产。

本项目的目标不是替用户选股，而是：

> **持续检查用户持有一只股票的理由是否仍然成立，并在关键事实发生变化时提供及时、准确、可追溯的证据。**

### 差异化方向：投资论点监控

用户可以为股票维护结构化的投资论点及反证条件，例如：

```text
股票：AAPL

投资论点：
服务业务是未来三年的主要增长动力。

反证条件：
1. 服务收入同比增速低于 10%；
2. 服务收入增速连续两个季度放缓；
3. 毛利率下降超过 2 个百分点。
```

系统将自然语言意图转换为经过用户确认的确定性规则，并持续监控相关数据：

```text
建立投资论点
    ↓
定义支持条件与反证条件
    ↓
获取并标准化市场、财务与事件数据
    ↓
纯代码计算指标并执行规则
    ↓
产生带证据的事件
    ↓
LLM 负责摘要、归因与不确定性说明
    ↓
用户反馈并更新投资论点
    ↓
形成长期决策与复盘记录
```

### 护城河建设

项目重点积累以下难以被通用 Agent 自动替代的资产：

1. **用户投资研究状态**
   - 投资论点、反证条件、关注指标和个性化阈值；
   - 论点的历史版本、状态变化和决策记录；
   - 用户长期形成的研究工作流与上下文。

2. **时间点正确的历史数据（Point-in-Time Data）**
   - 区分报告所属期间、公开时间、系统发现时间和修订时间；
   - 确保历史分析只使用当时已经公开的信息，避免未来数据泄漏；
   - 支持事件重放、历史回测和报告复现。

3. **多数据源质量与仲裁能力**
   - 不只接入多个供应商，还记录指标口径、更新时间和数据来源；
   - 对不同来源的冲突进行比较、质量评分和可解释仲裁；
   - 保存原始数据、标准化结果和修订历史。

4. **领域事件与证据关系**
   - 建立公司、指标、财报、事件、证据和投资论点之间的关系；
   - 将新事件关联到受影响的投资论点；
   - 每个结论都能追溯到原始文档、数据快照、计算公式和规则版本。

5. **反馈与效果数据**
   - 记录事件是否有价值、是否误报、是否重复以及用户采取的动作；
   - 持续评估事件命中率、误报率、通知价值和证据质量；
   - 根据真实反馈优化规则、阈值和信息交付方式。

### AI 与确定性工程的边界

系统严格区分事实、规则判断和模型推测：

```text
事实层：原始行情、财务数据、公告和新闻证据
规则层：涨跌幅、趋势、阈值及投资论点条件，由纯代码计算
AI 层：非结构化信息提取、证据归纳、事件解释和报告表达
```

LLM 不负责精确数值计算、阈值触发或交易决策。模型可以持续替换和升级，但标准化数据、确定性规则、证据链和用户研究状态保持稳定。

一份合格的事件报告应明确包含：

- 已验证的事实及数据时间；
- 被触发的规则和计算依据；
- 对应的投资论点或反证条件；
- 原始证据、引用位置和来源版本；
- 模型生成的解释及其不确定性；
- 使用的规则、提示词和模型版本。

### MVP 核心闭环

第一个可用版本优先实现以下闭环，而不是追求通用 Agent 能力：

```text
用户创建股票监控条件
        ↓
系统采集并持久化标准化数据
        ↓
确定性规则检测指标变化
        ↓
生成结构化事件和证据
        ↓
Web 控制台展示事件
        ↓
用户标记“有价值 / 误报 / 重复”
        ↓
LLM 对已确认的事实生成可追溯解释
```

短期 MVP 聚焦于少量高质量能力：

- 美股日线、PE、PB、EBITDA 等标准化数据；
- 价格异动、成交量异动和估值变化规则；
- 用户自定义监控阈值；
- 事件列表、证据详情和反馈入口；
- 基于确定性事件生成的 AI 解释。

SEC 财报、公司公告、电话会议、新闻聚类、投资论点版本管理和历史回测将在后续阶段逐步加入。

## 核心技术栈
* **核心框架**: Agno (Agentic Workflow)
* **后端工程**: Python, Celery (异步任务调度), Redis (消息队列/分布式锁)
* **数据存储**: PostgreSQL (任务状态持久化), Vector DB (知识库检索)
* **部署**: Docker / Docker Compose

## 架构设计亮点
本项目不仅是一个简单的 Agent 脚本，更着重于生产环境下的健壮性：

1. **事件驱动与任务调度**:
   - 采用 `Celery + Cron` 架构，实现对多源市场数据的实时轮询与异动触发。
   - 引入 Redis 分布式锁，确保在高并发与分布式场景下任务调度的幂等性与唯一性。
2. **AI-工程 分层架构 (可靠性核心)**:
   - **分层处理**: 明确界定大模型的职责范围。AI 仅负责非结构化信息的提取与逻辑归纳，所有数值计算、阈值触发与合规校验均由纯 Python 代码完成。
   - **防御性 AI**: 引入 Guardrails 机制，对 AI 输出进行格式与逻辑校验，确保分析结论具备可追溯性。
3. **高可用设计**:
   - 实现了完整的状态持久化（Checkpointing），支持 Agent 会话状态在系统中断后的热恢复。
   - 采用异步解耦设计，确保 AI 推理接口的波动不会阻塞基础数据的采集与任务调度。

## 使用方法

这个项目提供两个功能：
1. 个股追踪：用户选定个股名称和需要追踪的指标，系统自动化监测指标变化并生成报告。用户可以用自然语言控制报告的格式。
   - 线上即时聊天：agent 通过数据和网络搜索结果回答用户的问题。
   - cron 任务：agent 定时检查指标变化并通过社交媒体通知用户。

2. 事件驱动：用户制定重要事件（例如伯克希尔的ceo换人，股价涨跌幅超过某一程度）。agent 自动监测事件并立即通知用户
